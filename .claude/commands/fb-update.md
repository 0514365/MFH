이번 주 앱 데이터(최근 7일 일지·사진캡션·인사이트)를 분석해 **Facebook 게시안 2~3개(문구+추천사진+해시태그)** 를 만들어 Supabase(weekly_fb)에 저장한다. 분석 주체는 Claude Code(구독·종량제 0). 사진은 이미 생성된 캡션만 활용한다(비전 재분석·추가 비용 0).

## 절차

0. **클립 정리** — `media/inbox/` 에 파일이 있으면 먼저 `python3 scripts/index-media.py` 로 `media/raw` 정리·`media/index.md` 갱신(작업지시서의 [영상 클립] 목록이 여기서 나온다).

1. **작업지시서 받기** — 다음을 실행한다:
   `npx tsx scripts/fb-pull.ts $ARGUMENTS`
   인자가 없으면 기본 최근 7일. stderr 의 한 줄 요약은 무시하고, **stdout 전체가 작업지시서**다.

2. **분석·작성** — 작업지시서를 **그대로 충실히 따라** 게시안 2~3개를 작성한다. 가드레일을 **절대 위반하지 않는다**:
   - 온두라스 정치는 정당·인물 거명 없이 항상 중립.
   - 인물·아동의 실명·식별정보 금지(프라이버시). 캡션·일지에 없는 사실을 지어내지 않는다.
   - 따뜻하고 담백한 보고체 — 과장·모금 압박 금지, 감사·동행(기도) 요청 중심.
   - 추천 사진의 `path` 는 작업지시서 **[사진 목록]의 path 를 그대로** 옮긴다(임의 경로 금지). 캡션 있는 사진 우선.
   - 요일·인원은 일지 그대로 — 날짜의 실제 요일 확인(토요일 어린이 예배를 "주일"로 쓰지 않음), "모두 왔다" 류 과장 금지.
   - **릴스 자막은 보고체가 아니라 구어체**(작업지시서 [릴스 자막 규칙]) — 장면당 8~18자, `~했습니다` 금지, 장면 전체를 한 호흡의 이야기로 먼저 쓴 뒤 쪼갠다.
   - **릴스는 맥락 먼저** — 장면부터 고르지 않는다. 그 주제의 일지를 다시 읽고 게시안 문구를 쓸 때처럼 이야기 줄거리(상황·걱정 → 일어난 일 → 느낀 것·말씀 → 고백·기도)를 먼저 짠 뒤, 줄거리를 자막으로 나누고 거기에 맞는 사진·클립을 고른다. 자막은 화면 설명이 아니라 일지의 이야기를 전하는 내레이션이다(자막만 이어 읽어도 그날 일지의 흐름이 전해져야 한다).
   - **릴스는 한 주제 집중** — 게시안 하나처럼 한 가지 주제(한 사역·한 날)만 다루고, 사진·클립도 그 주제의 것만 쓴다(여러 사역을 섞지 않는다).
   - **릴스 기본 길이 약 45초**(표지 4 + 장면 6~8개 + 마무리 4 · 전환마다 0.6초 겹침 → 장면 `dur` 합계 = 37 + 0.6×(장면 수+1), 장면 7개면 약 42초). 클립 6~8초, 사진 4~5초.
   - **그 주제의 [영상 클립]이 있으면 반드시 클립 장면을 쓴다.** 클립은 캡션이 없으니 ffmpeg 로 프레임을 뽑아 내용을 직접 보고, 내용으로 일지와 짝짓는다(파일명 날짜는 어긋날 수 있음 · 짝이 불분명하면 뺀다).
   - **클립 줌·좌우 이동** — 클립 장면마다 `motion`(in/out/left/right)·`zoom`(1.3~1.5)·`focus`(얼굴 위치)를 적어, 등장 인물 얼굴이 가능한 한 번은 크게 보이게 한다(넓은 장면은 좌우 훑기, 한두 명은 얼굴 쪽 줌인).

3. **결과 저장 파일 쓰기** — 작업지시서의 `[result.json 형식]` 그대로 `insights-archive/_fb/result.json` 에 Write 한다(폴더 없으면 만든다. 이 폴더는 gitignore).

4. **DB 저장** — 다음을 실행한다:
   `npx tsx scripts/fb-push.ts`

5. **릴스 영상 빌드** — result.json 에 `reel` 이 있으면(작업지시서 3번: 사진·클립 3개 이상일 때만 설계) 다음을 실행한다:
   `npx tsx scripts/make-reel.ts`
   → `media/out/reel-<week_start>.mp4` (약 45초 · 음악 없음 · 클립 현장음 포함). 우진이 폰으로 받아 FB/IG 앱에서 음원을 골라 게시한다.

6. **보고** — push·make-reel 출력(주차·게시안 수·추천사진 수·릴스 길이)을 한국어로 1~2줄 요약한다.

## 주의

- 저장 귀속 user_id 는 `.env.local` 의 `MFH_USER_ID`. 누락 시 push 가 안내 후 멈춘다.
- 같은 주(week_start) 재실행은 **덮어쓰기**(주차당 1행). 표시는 앱 `/facebook` 전용 페이지(멤버 읽기).
- **WebSearch 를 쓰지 않는다**(외부 뉴스 불필요 = 비용 0). 게시 자체는 추천만 — 우진이 보고 직접 올린다.
- Cowork(아이폰 원격)에서 `/fb-update` 수동 호출, 또는 주간 자동 루틴에 등록(둘 다 같은 스킬).
