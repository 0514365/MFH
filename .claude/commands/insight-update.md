MFH 인사이트를 데이터 기반으로 생성해 Supabase 에 저장한다. 분석 주체는 Claude Code(구독·종량제 0). 종량제 API 키는 쓰지 않는다.

## 절차

1. **작업지시서 받기** — 다음을 실행한다:
   `npx tsx scripts/insight-pull.ts $ARGUMENTS`
   인자가 없으면 기본 90일·7도메인. `--domains overall,journal,project,task,prayer,fruit` 처럼 부분집합을 주면 **그 도메인만** 작업지시서에 실린다(아침 루틴은 letter 제외). stderr 의 한 줄 요약은 무시하고, **stdout 전체가 작업지시서**다.

2. **분석·작성** — 작업지시서를 **그대로 충실히 따라** 작업지시서에 실린 도메인(기본 7개: overall · journal · project · task · prayer · fruit · letter) 인사이트를 각각 작성한다. 작업지시서에 없는 도메인은 쓰지 않는다.
   작업지시서에 내장된 가드레일을 **절대 위반하지 않는다**:
   - 기도제목 3원칙 — ① 온두라스 정치는 정당·인물 거명 없이 항상 중립 ② 사역 기도제목 1~2개로 압축 ③ 가정 평강·문제예방·사전축복 비중.
   - 따뜻한 목양적 동행의 톤(평가·코칭 아님).
   - 인물·아동 실명/식별정보 금지(프라이버시).
   - 기록에 없는 사실을 지어내지 않는다. 데이터가 부족하면 솔직히 적는다.

   각 도메인을 회수 양식으로 감싼다(작업지시서 하단 양식과 동일):
   ```
   ===MFH-INSIGHT===
   LENS: <도메인 키>
   PERIOD: <pull 이 지정한 기간 그대로>
   ---
   <본문>
   ===END===
   ```

3. **결과 저장 파일 쓰기** — 작성한 블록을 모두 이어 `insights-archive/_result.md` 에 Write 한다(이 폴더는 gitignore).

4. **DB 저장** — 다음을 실행한다:
   `npx tsx scripts/insight-push.ts insights-archive/_result.md`

5. **보고** — push 출력(도메인별 ✓/✗ 저장 결과)을 한국어로 1~2줄 요약한다.

## 주의

- push 는 content·기간을 갱신한다. **내용이 실제로 바뀐 도메인은 별점·메모를 초기화**(옛 평가가 새 내용에 따라붙지 않도록)하고, **"편지에 담기"(in_letter)는 보존**한다. 내용이 그대로면 별점·메모도 유지된다. 영구 보존이 필요한 인사이트는 앱의 "보관"을 쓴다.
- 저장 귀속 user_id 는 `.env.local` 의 `MFH_USER_ID`. 누락 시 push 가 안내 후 멈춘다.
- **letter(다음 호 편지 방향)**: 핵심은 **전체 사역의 흐름·맥락 속에서 이번 달에 이루어진 일의 핵심을 골라 편지에 담을 내용을 정리**하는 것이다. 세 입력을 함께 반영한다 — ① 90일 분석 데이터 = 흐름·맥락 ② 「편지 기준점 — 직전 호」(호수·제목·summary) = 이미 보고·종결된 소재의 **제외 기준** + 그 뒤 흐름이 바뀐 것(응답·전환·중단)의 비교 기준 ③ 「직전 호 이후 기록」(직전 호 자료 기간 종료 다음날~오늘의 일지·할 일·프로젝트·QT 묵상·사진 캡션·온두라스 브리핑) = 이번 호의 새 재료. 직전 호 소재는 재서술하지 않고 새 국면이 있을 때 그 변화만 쓴다. 시간순 사건 나열 대신 방향 제안·개요로 정리한다. "편지 재료 — 최근 인사이트 + 내 피드백 신호"(별점·메모·편지에담기·보관)는 우진의 선호 신호로 반영한다. **온두라스 소식은 작업지시서에 실린 `honduras_news` 브리핑 안의 사실만** 쓴다 — WebSearch 하지 않고, 브리핑에 없는 수치·사건은 지어내지 않는다. letter 블록의 PERIOD 는 기준점 섹션에 적힌 기간(직전 호 종료 다음날 ~ 오늘)을 쓴다.
- balance(순수 집계)는 이 루틴에서 생성하지 않는다(앱에서 실시간 계산).
