# letter-design-qa — 발행 전 렌더 검수

`letter-designer` 는 Bash 권한이 없어 결과물을 렌더링해 볼 수 없다. **팀장(메인 세션)이 designer 산출물을 받은 직후, 우진에게 보여주기 전에** 이 절차를 돌린다.

## 범위
- **품질만 고친다**: 잘림·깨짐·사진 크롭·글자 크기·빈 공간.
- **2026년 디자인 고정을 지킨다**: 색·레이아웃·폰트 체계를 바꾸는 제안은 수정 목록에 넣지 않는다. 필요하면 "2027 참고"로 따로 적는다.
- **원고는 바꾸지 않는다.** 글이 넘치면 조판으로 풀고, 안 되면 우진에게 묻는다.

## 1. 기계 점검
```bash
python3 letter-templates/tools/qa-render.py letter-templates/issues/<월>
```
결과는 `issues/<월>/qa/` 에 생긴다(`report.md`, `cards-sheet.png`, `cards/`, `mobile/`). `--cards-only`, `--mobile-only` 로 한쪽만 돌릴 수 있다.

- **FAIL**(깨진 사진, 글자 잘림, 비율 왜곡, 작업 마커 노출, 구 계좌, 가로 넘침) = 반드시 수정.
- **WARN**(작은 글자, 낮은 대비, 저해상도, 빈 띠) = 캡처를 보고 판단. 머리글·쪽번호·영문 라벨처럼 고정 요소는 이미 제외되어 있다.

## 2. 눈 검수 (Read 로 PNG 를 직접 본다)
`cards-sheet.png` 로 전체 리듬을 먼저 보고, 표지와 WARN 이 있는 카드, 인물 사진 카드는 `cards/card-NN.png` 로 확대해 본다. 모바일은 `mobile/page-NN.png` 를 전부 본다.

| 항목 | 기준 |
|---|---|
| 얼굴 | 크롭에 잘리거나 글자·배지에 가린 얼굴 없음 |
| 사진 | 비율에 맞는 프레임, 사역 사진 위에 제목 없음, 같은 사진 중복 없음 |
| 빈 공간 | 하단이 비면 사진 확대·추가로 채움 (`letter-designer` §9-2) |
| 글자 크기 | 카드 본문 ~29px · 기도 ~24px, 모바일 본문 ~18px |
| 행 정렬 | 본문과 사진 하단 높이가 맞음, 면 끝 한두 글자 고아 줄 없음 |
| 위계 | 2초 안에 제목→사진→본문 순으로 읽힘 |
| 일관성 | 같은 역할의 요소는 면마다 크기·색·간격이 같음 |
| 번호 | `NN / 총면수` 연속, 호수 `MFH #YYMM` 일치 |
| 마무리 | 기도제목은 마무리 카드 한 곳, 계좌·SEED 로고·QR·링크 정상 |

사진의 인물·내용 판단은 사람이 봐야 하는 영역이다. 불확실하면 추측하지 말고 우진에게 그 면을 짚어 묻는다.

## 3. 비평 프레임 (선택)
Design 플러그인이 로드된 세션이면 `/design:design-critique` 와 `/design:accessibility-review` 를 캡처에 적용한다. 로드되지 않았으면(플러그인은 세션 재시작 후 로드됨) 위 표로 충분하며, 이것 때문에 작업을 멈추지 않는다. 플러그인의 일반 제안(디자인 시스템 변경 등)은 위 **범위** 규칙으로 걸러낸다.

## 4. 수정·재검수
1. 수정 목록을 면 단위로 만든다: `카드 07 — 하단 380px 빈 띠 — 사진 확대`.
2. 팀장이 직접 고치거나 `letter-designer` 를 재호출한다.
3. `qa-render.py` 를 다시 돌려 **FAIL 0** 을 확인한다.
4. 우진에게는 `FAIL 0 · WARN n`, 고친 항목, 남겨둔 WARN 과 그 이유를 짧게 보고한다. "확인했다"는 말만 쓰지 말고 실제 수치를 적는다.
5. 최종본은 `letter-assembler` 도 같은 도구로 다시 돌려 `qa-report.md` 에 결과를 남긴다.
