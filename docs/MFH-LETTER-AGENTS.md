> 첫 버전: 2026-06 · **현재 v2.0** (2026-06 2차 리허설로 팀·프로세스 안정화).

## 0. 이 문서의 위치

- **무엇**: 팀의 *합의·관계·핸드오프 계약*. (이 문서 = 헌법)
- **실행 정의**: `.claude/agents/letter-*.md` 5개. (각 에이전트가 실제로 읽고 그 역할로 동작)
- **사람이 검토**: 이 문서 + 정의서 5개를 우진이 하나씩 확정.

## 1. 팀 구성 (아키텍처)

```
당신(우진)
   ↕   ← 모든 요청·승인은 여기로만 (서브에이전트 직접 대화 없음)
팀장 = Claude (오케스트레이터: 호출·중계·정합성·QA 게이트)
   ├─ 1. collector    자료수집·사진인덱싱
   ├─ 2. strategist   방향 [2~3안]          ← 다양성
   ├─ 3. writer       원고 + 이미지매핑 (제목·리드 N안)
   ├─ 4. designer     디자인 시안 [2~3개 병렬]  ← 다양성
   └─ 5. assembler    도메인 QA·통합·출력
```

**관계 규칙**
- 창구는 팀장 하나. 서브에이전트끼리 직접 대화하지 않고 **전부 팀장을 경유**.
- 각 단계 사이에 **▶ 우진의 승인 게이트**. 승인 전엔 다음 단계로 안 간다.
- 다양성 단계: 팀장이 **병렬로 N개 호출 → 나란히 제시 → 우진 선택 → 선택안만** 다음으로.

## 2. 에이전트 5종 요약

| # | 에이전트 | 역할(1줄) | 입력 | 출력(계약) |
|---|---|---|---|---|
| 1 | `letter-collector` | 그달 일지·사진(다중)·인사이트를 모아 정리·인덱싱, 누락자료 질문 작성 | 대상 월 | `materials.md` · `photos/` · `photo-index.md` |
| 2 | `letter-strategist` | 자료 분석 + **웹검색** → 방향 2~3안 + **구성 개요(타이틀·부제·사실 골자·사진·기도 배분)** | 1의 출력 | `direction.md` |
| 3 | `letter-writer` | 확정 개요로 **사실 보고 본문(완성 초안)** + 글↔사진 매핑 | 2의 확정 개요 | `manuscript.md` · `image-map.md` |
| 4 | `letter-designer` | 마스터 HTML → 그달 시안 2~3개 | 3의 출력 + 사진 | `variants/letter-*.html` → `letter.html` |
| 5 | `letter-assembler` | 도메인 규칙 QA·최종 통합·출력 | 3+4 확정본 | `MFH-XXXX.pdf` + 포트폴리오 등록 메모 |

## 3. 핸드오프 계약 (단계 간 파일)

작업 폴더: `letter-templates/issues/<YYYY-MM>/` (gitignore). 형식을 못박아 단절을 막고, 우진이 중간 산출물을 직접 열어볼 수 있게 한다.

```
letter-templates/issues/<YYYY-MM>/
├─ materials.md      (1) 일지 텍스트 + 인사이트(★편지적용) + 중보연계
├─ photos/           (1) 원본 사진 파일
├─ photo-index.md    (1) 사진별 캡션·날짜·장소·추천용도
├─ direction.md      (2) 방향 2~3안 + 추천 + 3단 골격
├─ manuscript.md     (3) 확정 원고 (표지·내지·마무리·기도제목)
├─ image-map.md      (3) 글블록 ↔ 사진 매핑표
├─ variants/         (4) 디자인 시안 letter-A.html, letter-B.html …
├─ letter.html       (4) 선택·확정된 인스턴스
└─ MFH-XXXX.pdf      (5) 최종 출력
```

**계약 원칙**: 각 에이전트는 *위 자기 출력 파일만* 책임진다. 다음 에이전트는 *앞 단계 출력 파일만* 입력으로 받는다. 그 외 맥락이 필요하면 팀장이 채운다.

## 4. 다양성 정책

| 단계 | 다양성 | 형태 | 비용 |
|---|---|---|---|
| ② 방향 | ✓ 기본 | 방향 2~3안 + 추천 (텍스트) | 낮음 |
| ③ 글 | △ 부분 | **제목·리드 문구만** 2~3안, 본문은 단일 | 중간 |
| ④ 디자인 | ✓ | **시안 2~3개 병렬** → 선택 | 중간 |
| ① 수집 · ⑤ 조립 | ✗ | 단일 (발산 불필요) | — |

- 본문 전체를 여러 벌 쓰지 않는다(비용). 발산이 가치 있는 지점에만 다양성을 둔다.
- **다양성 흐름**: 병렬 생성 → 팀장이 차이점을 한눈에 비교표로 제시 → 우진이 선택(또는 "A의 톤 + B의 사진배치" 식 혼합 지시) → 선택안만 확정.

## 5. 오케스트레이션 규칙 (팀장)

**승인 게이트** — 단계마다 멈추고 보고·확정받는다. 임의 직진 금지.

**변경 요청 라우팅** — 우진은 항상 팀장에게 요청. 팀장이 규모를 보고 분배:

| 변경 유형 | 예 | 경로 |
|---|---|---|
| 사소·1줄 | 오타, 색 hex 하나, 여백 | 팀장 직접 (에이전트 호출 안 함) |
| 디자인만 | 표지색, 사진 배치, 폰트 크기 | `designer` 1개 재호출 |
| 글만 | 문구·기도제목 | `writer` → `designer` 반영 (연쇄) |
| 사진 교체 | 다른 사진 | (필요시 `collector`) → `writer` 매핑 → `designer` |
| 방향 전환 | 컨셉 자체 | `strategist`부터 (드묾) |

**정합성 책임** — 서브에이전트는 자기 산출물만 안다. 전체 톤·정합성·`issues/<월>/` 동기화는 **팀장이 최종 책임**진다.

**미확정 사항 핸드오프** — 어느 단계에서 사실이 부족해 "다음 단계로 넘기고 추후 결정"으로 합의되면, 팀장은 그 미확정 주제를 **다음 에이전트 호출 프롬프트에 명시**하고, 해당 에이전트는 그 부분을 **임의로 지어내지 말고 잠정 처리(미정·괄호표기)한 뒤 산출물에 `[미확정]` 표시**를 남긴다. 미확정 꼬리표는 해소될 때까지 단계마다 따라가고, 최종 assembler QA에서 **잔여 미확정이 없는지** 점검한다.

**자료 기준 기간 확립** — 편지는 회계 마감처럼 매월 1~말일로 끊지 않는다. 팀장이 기간을 함께 주지 않으면 collector 가 **직전 호 기준 기간을 참고로 제시하며 역질문**해 확정한 뒤 수집을 시작한다(임의 가정 금지).

## 6. 공통 내장 규칙 (모든 에이전트 공유 헤더)

> 5개 정의서의 "내장 규칙" 항목에 동일하게 박아 톤 흔들림·누락을 막는다.

**도메인 (기도제목·정치)**
- 기도제목 순서 **[온두라스] → [사역] → [가정]** (항상). 타이틀은 "나라" 대신 **"온두라스"**.
- 3원칙: ① 온두라스 정치 **중립**(정당·인물 거명 금지) ② 사역 기도제목 **1~2개 압축** ③ **가정 평강·문제예방·사전축복** 비중.
- 월간 편지 3단 구조: **온두라스 / 사역 / 선교사 가정**. 굵은 번호 제목 + 맥락 문단 + 대시 불릿. 번호 `MFH #YYMM`.
- **기도제목 요약은 마무리 카드가 겸한다**(별도 요약 카드 금지) — 마스터 `mfh-cardnews.html` 마무리 카드에 기도제목 그룹([온두라스]→[사역]→[가정])이 내장. writer·strategist 는 "기도제목 요약면"을 별도로 설계하지 않는다(중복 카드 방지).
- 연 주제 표기: **"2026년 주제 · 주님은 길을 내십니다"**.
- **온두라스 섹션 = 웹검색 기반**: strategist가 그달 온두라스 기상·경제·사회·치안 뉴스를 `WebSearch`로 확인해 시의성 있게 반영하되, **정당·인물·진영 거명 금지**, 정치 사안은 '사회 안정·치안·회복을 위한 중립 기도'로만. (근거: 기존 반자동 프로세스 PROJECT-INSTRUCTIONS/KNOWLEDGE)
- **앱 `letter` 인사이트(편지 초안 추천) 활용**: 앱이 생성한 '월간 기도편지(letter)' 인사이트 = 편지 방향 2~3안 + 3단 초안 추천. collector가 수집해 표시하고, strategist는 이를 **방향 설계의 출발점**으로 참조한 뒤 그달 자료·웹검색으로 검증·보완한다(중복 작업·앱 추천과 따로 놀기 방지).
- **내 피드백 신호(★별점·[편지에담기]·[메모]·[보관]) 우선**: 인사이트에 우진이 남긴 신호 = "이 재료를 편지에 담고 싶다"는 명시적 표시. collector가 `materials.md` 에 표기(★N·[편지에담기]·[메모])하고 `insight_scraps`(보관)를 별도 절로 모으며, strategist는 **[편지에담기] → 별점 → [보관] → [메모] 순으로 우선** 반영한다. 앱 letter 루틴 `lib/insightExport.ts` `buildLetterDigest` 와 동일 신호·형식(수집 스크립트 `fetch-letter-materials.mjs` V3).

**브랜드 (디자인)**
- 색 토큰: `--cool #DCC2C3`(더스티로즈) / `--accent #EFC8B8`(살구코랄) / `--navy #5E2A2B`(딥마룬). 월 변주는 `--cool`/`--accent` 두 색만 교체.
- 폰트: 제목 **Nanum Myeongjo** / 본문 **Pretendard** / 라벨·숫자 **Montserrat**.
- 톤: 강렬한 마룬·원색 거부, **파스텔·차분**. 이모지 절제.
- 로고 배치: `logo-primary`=표지헤더·마무리푸터 / `온두라스로고4`=마무리상단 / `mfh-icon`=CTA.

**언어·톤·기조**
- 모든 산출물 한국어. 따뜻하고 담백하게, 과장·상투어 절제.
- **사실 보고 우선** (2026-06 리허설 피드백): 사역 본문은 감상·추상·작위가 아니라 **"무슨 일 · 어디까지 · 앞으로 · 필요자원"의 사실 보고**. 타이틀은 **행사·목적이 분명**하게(추상·은유는 부제로), 기도제목은 **활동과 연결**.
- **은유·추상은 제목·부제에만, 본문은 사실 평서문** (★2606 재지적 — 최우선 QA): 주제어("발걸음/자리/걸음/길/터/씨앗" 등)를 본문에서 상징으로 반복하지 않는다. 본문은 누가·언제·어디서·무엇을 했는지 그대로. **팀장은 writer·designer 산출을 받을 때마다 "본문에 은유·추상·작위 문장이 있는지"를 면 단위로 점검**해 우진 검토 전에 걸러낸다(지침은 있었으나 실행에서 새던 지점 — 게이트로 못박음).
- **모바일 지면 원칙**: **1면 1주제**, 사진을 텍스트보다 **부각**, 사진 많으면 **2면 분할**, 사진 없는 주제는 **추가사진 요청**.
- **모바일 폰트 스케일(가독성 — 디자인 바뀌어도 유지)**: 본문 ~18px·줄간격 ~1.7 / 섹션 제목 26~30px 볼드 / 기도 라벨 18~20px·내용 ~17px / 캡션 ~12.5px(한 줄) / 표지 제목 40px+. (2026-06 실기기 확정)
- **모바일 우선 제작 → 카드뉴스 변환**: 편지는 **모바일 HTML을 먼저 완성**하고, 그 내용을 **카드뉴스 PDF(4:5)로 변환**한다(메인=모바일, PDF=오프라인 게시). 내용은 동일하게 쓰고, 지면 특성상 designer가 **레이아웃 일부 변경·사진 일부 추가**로 카드뉴스를 완성한다.
- **단계 승인 강화**: strategist는 **개요**(사실 골자·사진 계획·기도 우선순위·분량)를, writer는 **완성 초안 + 사진 배치 계획**을 각각 우진에게 승인받고 다음으로.

## 8. 매달 가동 절차 (런북)

```
0. **가동 — 디자인 선행 · 수집 병행**: 우진이 "○월호 만들어줘"라고 하면, 팀장은 **두 갈래를 동시에** 연다 —
   - ① **Variant 모바일 디자인 프롬프트를 먼저 제시.** 우진이 variant.ai 에서 **다양한 컬러·레이아웃의 모바일 편지 시안**을 탐색해 그달의 **큰 디자인 방향을 먼저 결정**하도록, 팀장이 그 프롬프트를 작성해 건넨다(구조·정신·폰트 스케일·도메인 규칙은 `mobile-variant-prompts.md` 기준, 컬러·레이아웃 다양성은 Variant 몫).
   - ② **collector 착수(병행).** 우진이 디자인을 탐색하는 동안 팀장은 collector를 호출해 자료수집을 진행한다. 대상 호수·**자료 기준 기간**도 이때 확정(미지시면 collector 가 직전 호 기준으로 역질문).
   - ※ 주제 선정(strategist)은 이 디자인 탐색·수집 **다음**이다. 디자인은 주제와 독립적으로 먼저 큰 틀을 잡아 둔다.
1. collector  → materials·photos·photo-index         ▶ 검토 (누락자료 보완)
2. strategist → **주제 후보 2~3** → **기조문**(도입·강조점) → **개요문**(사실 골자·사진·기도)  ▶ **주제 선정 → 기조문 승인 → 개요문 승인**
3. writer     → manuscript·image-map (완성 초안)       ▶ **본문 전문(축약 없이) 한 문장씩 검토·수정 → 전체 확정 후 designer**
4. designer   → 모바일 letter.html (Variant 베이스·1면1주제)   ▶ 모바일 디자인 확정

```

각 ▶ 에서 우진 승인 후 다음으로. 변경은 §5 라우팅대로.
