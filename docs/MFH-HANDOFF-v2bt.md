## 이번 세션 작업

### 1. 앱 버전 공식 지정 → 3.0.0
- 배경: `package.json` 이 Next 기본값 `0.1.0`(stale)로 방치, 버전 트래킹은 핸드오프 코드네임(`v2bX`)으로만. 실제론 매일 실사용 + 공개 포트폴리오 배포(`/p/mfh`) 상태로 0.1.0 은 명백히 어긋남.
- 판단: "4모듈 기록앱(~2.x)" → 선교편지 5-에이전트 + 7도메인 인사이트 + 자동화 스킬(QT·뉴스·FB·캡션·비서) + 공개 포트폴리오 = **제품 정체성 도약(MAJOR)**. 우진 체감 2.0 → 큰 변화 후 **3.0**.
- 반영: `package.json` version `0.1.0` → **`3.0.0`**. git tag **`v3.0.0`**.
- 공개페이지(`/p/mfh`) 버전 표기는 **안 함**(후원자 대상 불필요 — 우진 결정).

### 2. CLAUDE.md §8 — 버전 체계 + 증가 제안 규칙 신설
- 제목을 "빌드 단계 / **버전** / 현재 위치" 로 개편.
- SemVer 단일 출처(SoT) = `package.json` 의 `version`. 핸드오프 코드네임(`v2bX`)은 **세션 추적용으로 별개** 유지.
- **버전 증가 제안 규칙(필수)**: 의미 단위 작업(커밋 단위)을 마칠 때마다 Claude 가 이번 변경 등급 + 다음 버전을 **한 줄로 제안** → 우진 승인 → `package.json` 반영. PATCH(`3.0.x`)=버그·소소한 텍스트/스타일, MINOR(`3.x.0`)=하위호환 기능 추가(새 화면·모듈·스킬), MAJOR(`x.0.0`)=제품 축 도약·호환 깨짐.

## 핵심 메모 (다음 세션)

- **버전 운영**: 카운팅은 *다음* 기능/수정 작업부터 시작(예: 버그픽스 → `3.0.1`, 새 모듈 → `3.1.0`). 매 커밋 직전 Claude 가 등급+번호를 제안하게 돼 있음(CLAUDE.md §8) — 누락되면 우진이 "버전?" 으로 환기.
- **핸드오프 코드네임은 앱 버전과 별개 트랙** — 계속 `v2b` 시퀀스로 이어감(다음 `v2bu`). 앱이 3.0 이라고 핸드오프를 리셋하지 않는다.
- 편지 산출물·발송 호 상세 메모는 `v2bs` 핸드오프(`docs/archive/`) 참조.
