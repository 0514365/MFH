## 요약 (코드를 안 읽어도 되게)
- **구분 필터**: 선지급 = 입금 계좌가 미수금인 이체, 회수 = 출금 계좌가 미수금인 이체. 선택 없음 = 전체. 내역 딥링크 `?gubun=` 과 검색 `?g=` 는 쉼표로 여러 개.
- **필터 기억**: 필터 상태는 화면별 키(`ledger`·`search`)로 계속 저장하고, 행을 눌러 수정 화면으로 갈 때만 복원 표시를 남긴다. 탭으로 새로 들어오면 복원하지 않는다. 스크롤 위치는 복원 안 함. 한계 — 행을 누른 뒤 뒤로 오지 않고 다른 탭으로 나가면 다음에 그 화면을 열 때 한 번 복원된다.
- **인라인 수정**(`app/(app)/accounting/TransactionList.tsx`): 칸 클릭 = 그 자리 입력, Enter·칸 밖 = 저장, Esc = 취소, Tab = 옆 칸. 수정 대상이 아닌 칸(구분 칩 등) 클릭 = 세부 화면. 모바일 카드 목록은 종전대로.
  - 항목 = 수입·지출 / 구매처 = 수입·지출·선지급 / 금액 = 수입·지출·같은 통화 이체. **조정·통화가 다른 이체의 금액은 잠김**(세부 화면에서).
  - 금액은 그 거래 통화의 원금을 고친다. USD 환산은 2026-09 이후 DB 트리거(`acct_inout_apply_fx`)가 다시 정한다. 통화 열을 접으면 환산$ 칸에서 원금 입력.
  - 저장은 기존 `bulkPatchInout` 한 건 호출. 저장 직후 화면은 낙관 반영(`overrides`) → `router.refresh()`.

## 카드 대조 방법 (다음에 그대로 쓰기)
1. 명세서 1면 요약: `Saldo Anterior − Pagos + Compras + Cargos = Saldo Total`. 여기에 마감 후 내역(Movimientos Actuales)을 더하면 갚을 금액.
2. 카드별 합계(`TOTAL DE TARJETA`)는 그 카드 거래 **뒤**에 인쇄된다(앞이 아님). 판독한 금액 합을 이 합계와 맞춰 검증.
3. 앱 잔액은 계좌 통화 버킷과 USD 버킷을 따로 본다(`getAccountBalances` 와 같은 방식).
4. 상환은 전표가 들어온 금액만 갚으므로, 상환 전날·당일 사용분은 다음 상환으로 넘어간다.
