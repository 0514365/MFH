## 체계 요약 (코드를 안 읽어도 되게)
- **미수금(선지급) 계좌**: 우진이 앱에서 생성(HNL) → patch120 으로 `kind='미수금'`. 앱은 이 유형으로 알아봄(`receivableAccount`). 자산 탭 HNL 그룹에 표시, 잔액 = 아직 못 받은 돈.
- **선지급** = 이체(지불계좌 → 미수금). **회수** = 이체(미수금 → 입금계좌, `settles_inout_id` 로 선지급 연결). DB `gubun` 은 둘 다 `'이체'`, 화면 칩만 선지급/회수.
- 상태 판정은 USD 기준, 환차 허용 = max($0.5, 2%). 미수금 통화 금액은 양쪽 모두 알 때만 표시(선지급: 같은 통화면 원금, 다른 통화면 입금 금액 · 회수: 원금).
- 승인대기 「선지급」: USD 카드 결제는 입금 금액을 비워 USD 로 반영 — 필요하면 기록 폼 수정에서 입금 금액(HNL) 입력.
- 수정 모드는 단일 연결 콤보. 분할 저장된 회수 행은 각각 독립 행(삭제·수정 개별).

## 우진 확인이 필요한 것 / 미정
- 못 받게 된 선지급의 손실 처리 규칙(§5-6: 차액을 지출 사역비/행정·기타 1건)은 문서에만 있고 버튼은 없음. 건수가 생기면 「손실 처리」 버튼 검토.
- 승인대기 **일괄 선지급**(여러 행 체크 후 선지급)은 없음 — 행별 버튼만.
- 자산 탭 미수금 행은 HNL 그룹 안에 섞여 있음. 「받을 돈」 별도 그룹은 미구현.
