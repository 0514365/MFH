## 이번 세션 작업

### 배경 — 우진 요청
"인터넷이 안 되면 앱이 전혀 안 열리고, 사진 로딩이 느리다(온두라스 회선). 일부 정보를 기기에 저장 후 복구 시 동기화 + 목록은 축소 썸네일·클릭 시 원본."
→ 진단: ① SW(`public/sw.js` V4)가 캐시를 안 함 + 전 페이지 `force-dynamic` SSR → 오프라인 미로딩. ② 사진 원본 그대로 업로드·표시(리사이즈/썸네일/lazy 없음) → 로딩 지연.
→ 3단계 로드맵 합의: **1.사진 최적화 → 2.오프라인 읽기 → 3.오프라인 쓰기+동기화.** 위험·효과순으로 1단계만 이번에.

### 1. 사진 최적화 (3.1.0) — 커밋 `6c2501a`
- **썸네일 파이프라인**: 업로드 시 브라우저 Canvas 로 512px WebP 썸네일 생성(`lib/imageResize.ts`), 원본은 그대로 보존(우진 선택). 목록·갤러리는 썸네일 + `loading="lazy"`, 클릭(라이트박스)·ZIP 은 원본.
  - `JournalPhoto.thumb_path` 추가(JSONB — **DB 마이그레이션 불필요**). resolve/collect/edit/delete 전 경로에 thumb 보존.
  - 변경: `lib/{types,imageResize,photo,journalPhotos}.ts`, `app/journal/{JournalForm,PhotoCollage,page,[id]/page}.tsx`, `app/photos/{page,PhotoGalleryClient}.tsx`.
- **백필**: `scripts/backfill-thumbnails.ts`(sharp, 멱등, `--dry`, 레거시 단일→photos 승격). `npm run backfill:thumbs`. **실행 완료 — 기존 59장/26일지 썸네일 생성, 실패 0, 멱등 재확인.**
- 효과: 목록 사진 수MB → ~22KB(100배 안팎↓). 신규는 배포 즉시·기존은 백필 반영.

### 2. 원본 저장 버튼 (3.1.1) — 커밋 `b007850`
- 일지·갤러리 라이트박스에 **`원본 저장`** 버튼 추가(`lib/download.ts` = fetch→blob 강제 다운로드, signed URL 교차출처 대응, 진행 상태 표시). 편지·인쇄용 고화질 확보.

## 핵심 메모 (다음 세션)

- **남은 핵심 = 오프라인 지원(우진 1순위 요청).** 1단계는 사진만 한 것 — "인터넷 안 되면 앱이 안 열림"은 아직 미해결.
  - **2단계(오프라인 읽기)**: SW 앱셸 캐싱 + 최근 일지·할일·썸네일 IndexedDB 저장 → 회선 끊겨도 앱 열림·열람. 단 전 페이지 `force-dynamic` SSR 이 걸림돌 — 일부 클라이언트 렌더 전환 필요. 중~대 규모.
  - **3단계(오프라인 쓰기+동기화)**: 작성 큐 → 복구 시 자동 업로드. 충돌·사진동기화로 가장 복잡. 2단계 안정화 후.
- **첨부 이미지(할일·프로젝트)는 썸네일 미적용**(이번 범위 = 일지 사진만). 같은 패턴으로 확장 가능 — `app/photos/page.tsx` 첨부 분기는 thumbUrl=원본으로 채워둠.
- 썸네일 규격: 512px WebP q0.72(`lib/imageResize.ts`·백필 동일). 추가 스토리지 미미(59장 ≈ 1.3MB).
- 의존성: `sharp`(devDep, 백필 전용) 추가됨. `npm run backfill:thumbs` 는 `.env.local` 의 `SUPABASE_SERVICE_ROLE_KEY` 필요.
