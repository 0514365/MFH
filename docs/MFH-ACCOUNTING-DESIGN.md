# MFH 회계관리 모듈 설계 (A안 — 앱 입력 → 노션 저장)

> 작성: 2026-06-25. 노션 회계(SoT) 위에 앱 입력 UI 를 얹는 **A안**. 입력은 앱(조건부·자동 로직), 저장·운영·조회는 노션 유지.
> 관련: `lib/notion.ts`(read + write 예정) · `app/accounting/`(신규) · 노션 입출금기록 DB.
> 노션 ID: 입출금기록 **database** `37c15af9-28ad-817b-94da-c05e3f2e7e3a` / **data source(collection)** `37c15af9-28ad-817a-a360-000b137b8b1e`. 후원자 DB `fe45d45f-c7c0-40ce-a329-525e46a83ef3`. (REST 는 database id, MCP 는 collection id — 혼동 시 404)

---

## 1. 결정 배경 (왜 A안)

- 노션 = 회계 SoT. 그러나 요구한 입력 자동화 중 **조건부 콤보(구분별 항목·계좌)·이름→후원자 자동연결은 노션 네이티브로 불가** → 앱 커스텀 폼이 필요.
- 앱은 **저장소를 안 가짐**. 노션에 직접 write/read → 단일 SoT, 동기화 충돌 0(양방향 sync 함정 회피).
- 노션 직접 입력과 앱 폼 입력 **병행 가능**(둘 다 같은 노션 입출금기록에 행 추가). 앱 폼이 미완이어도 노션이 받쳐 회계가 멈추지 않음 → **점진 구현**.

## 2. 아키텍처

- **라우트**: `app/accounting/page.tsx` — 첫 화면 = 입력 폼 + 최근 거래.
- **진입**: 홈 벤토 `ModuleTile` (마스터 전용 `isMaster`, 기존 Supporters 패턴). `app/page.tsx`.
- **권한**: 마스터 전용(회계 민감).
- **데이터 경로**: 노션 REST API — read(`POST /v1/databases/{id}/query`), write(`POST /v1/pages`). 토큰 `NOTION_TOKEN`(서버 전용). MCP query_data_sources 는 Business plan 필요(무료 플랜 400) → REST 만 사용.

## 3. 데스크탑 / 모바일 UI 구분

앱 전체가 `max-w-md` 모바일 PWA. 회계는 **첫 데스크탑 대응**.

- **데스크탑(md+)**: 스프레드시트형 — 입력 필드가 **가로 한 줄**, 연속 입력(엔터/탭), 아래 최근 거래 **테이블**. 데스크탑이 주 입력처.
- **모바일**: **세로 단계 폼** + 거래 목록 카드(조회 보조).
- **구현**: 입력 폼은 `'use client'`(조건부 로직·자동계산), 레이아웃만 Tailwind `md:` 로 가로/세로 분기. 한 페이지(서버 컴포넌트)가 폼·목록을 담고, 데이터(콤보 옵션·최근 거래)는 서버에서 노션 read 후 전달.

## 4. 입력 폼 (필드 · 조건부 · 노션 매핑)

| # | 폼 필드 | 동작 | → 노션 컬럼 |
|---|---|---|---|
| 1 | **구분**(수입/지출 토글) | 항목·계좌 콤보를 거름 | `구분`(select) |
| 2 | **날짜**(기본 오늘) | | `날짜`(date) |
| 3 | **항목**(콤보) | 수입→수입항목만 / 지출→지출항목만 | `항목`(relation) |
| 4 | **이름** | 항목=후원금이면 후원자 콤보 + 신규/단체/무명 자유입력 | `이름`(title) |
| 5 | **통화**(KRW/USD/HNL) | USD 선택 시 환율 1 고정 | `통화`(select) |
| 6 | **금액(현지)** | 원통화 금액 | `원금`(number) |
| 7 | **환율** | 1 USD당 현지통화 | `환율`(number) |
| 8 | **환산(USD)** | `=금액÷환율` 자동계산(읽기전용) | `금액`(number) ★헌금합계 rollup 타겟 |
| 9 | **계좌**(콤보) | 수입→입금계좌 / 지출→지불계좌 | `입금계좌`/`지불계좌`(relation) |
| 10 | **후원자** | 이름이 후원자 목록과 일치하면 자동 연결(단체·무명은 빈 relation) | `후원자`(relation) |

조건부 로직 요약:
- 구분=수입 → 항목 콤보=수입항목(후원금·기타수입·중고판매·노션템플릿판매), 계좌=입금계좌.
- 구분=지출 → 항목 콤보=지출항목(사역비·생활비·주거·차량·통신·의료·자녀교육·수수료·행정기타·미용의류·특별비), 계좌=지불계좌.
- 항목=후원금 → 이름 필드가 후원자 콤보(+자유입력) 모드.
- 이름 == 후원자명 → `후원자` relation 자동 연결.
- 통화·금액·환율 변경 → 환산(USD) 실시간 재계산.

## 5. 환산 규칙

- **`금액(USD) = 원금(현지통화) ÷ 환율`**. 환율 = 1 USD 당 현지통화(예: 1400원/$, 25렘피라/$).
- 통화=USD → 환율 1, 금액=원금.
- 검산(현 데이터): 20,000원 ÷ 1400 = $14.29 · 500,000원 ÷ 1450 = $344.83 · 15,000,000원 ÷ 1365.7 = $10,983.4.

## 6. 콤보 데이터 (노션 read — 신규 함수)

`getAccountingOptions()` → `{ items: {수입:[…], 지출:[…]}, supporters: [{id,name}], accounts: [{id,name}] }`
- 항목 DB(`37c15af9-28ad-8111-…`): 이름·구분·페이지id(relation 연결용).
- 후원자 DB: 이름·페이지id.
- 자산 DB(`37c15af9-28ad-8110-…`): 이름·페이지id.

## 7. 저장 (노션 write — 신규 함수)

`createInoutRecord(payload)` → `POST /v1/pages`, `parent: { database_id: INOUT_DB }`.
- properties: `구분`(select), `날짜`(date), `항목`(relation), `이름`(title), `통화`(select), `원금`(number), `환율`(number), `금액`(number), `입금계좌`/`지불계좌`(relation), `후원자`(relation).
- 성공 → 폼 리셋 + 최근 거래 갱신(서버 액션 revalidate 또는 router.refresh).

## 8. 작업 순서 (효용/노력·의존성 기준 — 06-25 재개정)

**완료**: 입력 폼(수입·지출, 데스크탑 스프레드시트·모바일 세로, 조건부·환산·후원자 자동연결) + 금액 천단위 쉼표 + 컨트롤 높이 통일 + **거래 수정·삭제(앱)** + **영수증 files 컬럼(노션)**.

**Phase 1 — 입력 완결 ✅ 완료**
- ✅ 거래 수정·삭제(앱): 최근거래 행 `수정`→폼 편집 모드·`updateInoutRecord`, `삭제`→`archived`(휴지통, 복구 가능). 입력 오타·오류 즉시 대응.
- ✅ 영수증 `files` 컬럼(노션): 우진이 노션 모바일/데스크탑에서 사진 첨부(앱 개발 없음).

**Phase 2 — 메인 요약(앱)**
- 회계 페이지 상단에 이번달 수입 합·지출 합 + 계좌별 잔액(자산 `입금합USD`−`출금합USD` rollup read). 매일 여는 화면이라 효용 최대.

**Phase 3 — 리포트(앱)**
- 항목별 수입/지출 합 · 후원자별(2단계 연도별 집계 확장) · 계좌 잔액. Phase 2 집계 로직 재사용.

**Phase 4 — 다듬기**
- 모바일 입력 폼 최적화(통화+금액·환율+환산 짝짓기 등).

**Phase 5 — 고급**
- 이체·환전(계좌 간 이동·환전 기록, 빈도 낮음).

**노션에서 즉시(앱 개발 불필요)**: 항목 추가(항목 DB 행 추가 → 앱 콤보 자동 갱신) · 입력 수정(셀 편집) · CSV import/export(DB `⋯` 메뉴 내장) · 영수증(files 첨부).

## 9. 메모 / 주의

- ⚠ **손경희 데이터 오류**: 원금 100,000원인데 금액 14.29(=20,000÷1400, 김영동 값 추정). 실제라면 $71.43/월(×6 = $428.57). 우진이 노션에서 손경희 실제 후원액 확인 후 `금액` 수정 → 앱 합계 자동 정정.
- 노션 **컬럼 이름 유지 필수**(read·write 둘 다 의존). 순서·위치는 무관.
- 노션에 **빈 거래 2건** 잔존(금액·후원자 없음, 집계 자동 제외) — 우진이 노션에서 정리 가능.
- `이체`/`반복`/`미납` 구분은 제거됨 — 현 구분 옵션 = 수입/지출/이체(이체는 Phase 4).
- **브레인스토밍 검토(06-25)**: CSV·입력수정·항목추가·영수증은 노션 네이티브가 더 쉬움(A안 철학 — 노션 강점 활용). 앱 신규 개발은 **메인 요약·리포트**에 집중. 영수증은 입출금기록 `files` 컬럼 추가만으로 노션에서 첨부 가능.
